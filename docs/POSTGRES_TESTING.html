A Neon branch is a database copy, separate from a Git branch. Changes made in the child do not update its parent. Django then creates its own temporary test database inside that child branch, runs the tests, and removes the test database afterward.

Your usual manage.py runserver continues to use SQLite. PostgreSQL is selected only when a command explicitly chooses config.settings_postgres. Images stay in R2; automated tests use isolated media fixtures.

01 · Prepare

Open a new terminal

Keep your existing Django and frontend terminals running. In the new terminal:

cd /Users/kaancinar/Desktop/python-projects/kaan-gallery
export PATH="/opt/homebrew/opt/node@24/bin:$PATH"
set -o pipefail
neon --version
./.venv/bin/python -m pip check

Expected: Neon prints a version and pip reports no broken requirements. If Neon needs authentication, run neon login and complete browser sign-in.

The project is kaan-gallery, in AWS US East (N. Virginia). Connections are saved in ignored .env.local; project selection is saved in ignored .neon. Neither should be pasted into chat.

02 · Isolate

Create and select the development branch

Create it explicitly from main, without printing connection credentials:

neon branches create \
  --project-id shiny-smoke-23111194 \
  --parent main \
  --name dev-postgres-tests \
  --no-secrets

If Neon says this branch already exists, reuse it with the next command; do not reset or delete it.

neon checkout dev-postgres-tests \
  --project-id shiny-smoke-23111194
chmod 600 .env.local

Expected: Neon reports that dev-postgres-tests is selected and pulls its connection variables into .env.local. This changes the PostgreSQL connection file, not your code or SQLite database.

In the Neon console, open Branches and confirm that dev-postgres-tests appears under main.

03 · Verify

Run checks, migrations and tests

Paste this whole block into the same terminal. Full output is displayed and saved to /tmp/kaan-postgres-tests.log. It reads the branch’s direct connection privately, confirms the branch name, checks TLS, and runs Django. It never prints a connection string.

./.venv/bin/python - <<'PY' 2>&1 | tee /tmp/kaan-postgres-tests.log
import json
import os
from pathlib import Path
from dotenv import dotenv_values

link = json.loads(Path(".neon").read_text())
assert link.get("projectId") == "shiny-smoke-23111194", "Wrong project: stop."
assert link.get("branch") == "dev-postgres-tests", "Wrong branch: stop."
values = dotenv_values(".env.local")
assert values.get("NEON_BRANCH") == "dev-postgres-tests", "Stale env file: stop."
url = values.get("DATABASE_URL_UNPOOLED")
assert url, "Direct database connection is missing: stop."
os.environ["DATABASE_URL"] = url
os.environ["DJANGO_SETTINGS_MODULE"] = "config.settings_postgres"

import django
django.setup()
from django.db import connection
from django.core.management import call_command

with connection.cursor() as cursor:
    cursor.execute("SELECT 1")
    assert cursor.fetchone()[0] == 1
    assert connection.connection.pgconn.ssl_in_use, "TLS is required."
connection.close()
print("Development branch connected; TLS verified.")
call_command("check")
call_command("migrate", interactive=False)
call_command("test", interactive=True, verbosity=1)
PY

Expected: system checks pass, migrations apply or report none pending, and the suite ends with Ran 160 tests and OK, followed by test database cleanup. The count may increase as we add tests.

The block overrides the database URL only within this Python process. It does not change your saved pooled URL or switch the running app. The first Neon connection may take longer if compute has suspended; PostgreSQL tests also incur network round trips.

If something fails

Wrong branch / stale env: stop and repeat the checkout step. Do not bypass the assertions. Permission denied creating a database: verify the direct URL uses the branch’s owner role. Existing test database prompt: answer “no” and investigate before authorizing deletion. FAIL / ERROR: keep the branch and share the failing test name and sanitized traceback from /tmp/kaan-postgres-tests.log, with credentials removed. Do not repeatedly recreate the project.

Why the first PostgreSQL run failed

The image tests manually closed HTTP responses, which fired Django’s normal request-finished cleanup inside a test transaction. That closed PostgreSQL’s connection, causing later requests to report OperationalError: the connection is closed. SQLite’s in-memory test connection concealed the problem.

The test-only closing_response helper now closes responses using the same signal handling as Django’s test client. It still releases image files. Production connection handling, test assertions and image authorization remain unchanged.

Verified after the fix: all 160 tests passed on PostgreSQL (147.8 seconds) and SQLite (8.9 seconds). The PostgreSQL test database was removed normally. The development branch remains selected so you can follow the return-to-main step when ready.

04 · Return

Restore the workspace’s main connection

After saving the test result:

neon checkout main --project-id shiny-smoke-23111194
chmod 600 .env.local
./.venv/bin/python manage.py check

Expected: Neon selects main, refreshes its connection file, and the ordinary Django check passes using SQLite.

You can keep the development branch while investigating results. Once it is no longer needed, delete only dev-postgres-tests in the Neon console. Branches and their compute/storage consume your Neon allowances; do not leave unnecessary branches indefinitely.

What this does not deploy

This does not transfer SQLite records, switch your gallery to PostgreSQL, configure Render, or change kaancinar.com. The PostgreSQL settings still inherit local DEBUG/security defaults. After these tests pass, the next work is production settings and Docker, followed by a separately verified data transfer.
