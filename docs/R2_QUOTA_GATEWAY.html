Django sends a server-only secret to the Worker. A single SQLite-backed Durable Object processes quota changes in order, so simultaneous requests cannot spend the same remaining allowance. It reserves usage before making an R2 call.

The browser receives bytes through Django. It receives no storage secret or direct bucket URL. This workstation uses a private, Git-ignored connection file. Other checkouts use local filesystem storage unless configured; deployment environment settings take precedence.

GB uses decimal bytes. Each object reserves an extra 8 KiB for metadata. Files are limited to 10 MiB. The current date-only setup stops conservatively at December 10, 00:00 UTC. This is not a confirmed reset hour; automatic quota resets are disabled.

What happens on a request

  1. Authorize. Django checks visibility first. The Worker then checks its storage secret. Management actions require a separate control secret.
  2. Reserve. A read reserves a Class B operation; an upload reserves Class A and bytes. Metadata requests use the ledger without an R2 read.
  3. Access R2. Uploads create new keys only. Unexpected existing objects lock access for investigation.
  4. Return safely. Unavailable storage becomes a generic Django 503 with retry guidance. Responses use private/no-store caching.

Checks, alerts and recovery

  • Every 15 minutes, a scheduled check reconciles account-wide R2 analytics and retries pending alerts.
  • Failed analytics, snapshots older than 30 minutes, exhausted budgets or a manual lock stop billable access. Authorized deletes remain available.
  • Resend email or an optional HTTPS webhook receives durable warning events. Failed deliveries retry; stable IDs help reduce duplicates.
  • With the renewal hour unconfirmed, billing rollover retains all counters and stops billable access for review. A review alert is queued; manual unlock cannot bypass the hold.

A conservative cutoff, not a billing guarantee

Cloudflare analytics can lag. Other credentials, public URLs or other workloads can bypass reservations. Stored data still accrues usage while requests are stopped. Failed operations retain reservations and may stop service early; storage analytics can also remain high after deletion.

Workers and Durable Objects have their own allowances. Bot protection and public-route rate limits remain deployment work. Alerts are not live until a notification destination is configured and tested.
